# MAGeCK2 Governance

This document describes how the MAGeCK2 project is organized and how decisions are made. It is
intended to be lightweight and to grow with the project.

## Roles

### Users

Anyone who uses MAGeCK2. Users contribute by reporting bugs, requesting features, asking and
answering questions on the [user forum](https://groups.google.com/g/mageck), and improving
documentation.

### Contributors

Anyone who contributes to the project — code, documentation, tests, examples, issue triage, or
review. Contributions are made through pull requests (see [CONTRIBUTING.md](CONTRIBUTING.md)) and do
not require any formal status.

### Maintainers

Maintainers are responsible for the health and direction of the project. Their responsibilities
include reviewing and merging pull requests, managing releases, triaging issues, supporting the user
community, and stewarding the [roadmap](ROADMAP.md). The current maintainers are listed in
[MAINTAINERS.md](MAINTAINERS.md), and ownership of areas of the codebase is recorded in
[CODEOWNERS](CODEOWNERS).

## Decision making

The project operates by **lazy consensus**: most changes proceed when there are no sustained
objections from maintainers. Routine changes (bug fixes, documentation, tests) can be reviewed and
merged by any maintainer. Substantial changes — those affecting the public API, supported data
formats, or the project's direction — are discussed openly in an issue or pull request so that
maintainers and interested community members can weigh in before a decision is made.

When consensus cannot be reached, the lead maintainer makes the final decision, taking the
discussion into account.

## Becoming a maintainer

Contributors who have shown sustained, high-quality involvement — through code, review, and
community support — may be invited to become maintainers by the existing maintainers. There is no
fixed quota; the goal is to grow a healthy, diverse maintainer team over time.

## Changing this document

Changes to project governance are themselves proposed via pull request and are subject to maintainer
consensus.
